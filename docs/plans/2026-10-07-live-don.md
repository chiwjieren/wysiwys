# Live DON review path (branch `feat/live-don`)

Goal: reviews signed by a live Chainlink DON and delivered through the production Keystone forwarder on Solana devnet, so a report can no longer be forged by anyone running the simulator. `main` keeps the simulator path as the demo until this is stable.

## What changes

| Part | Change |
|---|---|
| Workflow | `execution: "tee" \| "don"` in the config. `tee` (default) keeps `cre.handlerInTee`. `don` registers `cre.handler`: the policy and Scorechain key come from Vault DON secrets in DON mode, and screening runs in node mode with identical consensus. Same decoder, policy, quorum reads and report. |
| Workflow config | `config.live.json`: production forwarder program `CXsKEJcs25TQEYU2e5jZ8QTPE3ffMLZhH6BWHrdcCCB5`, state `8QoomCQyPSkJ8WopJbX9B4HyvrFzziwvJdU8hZE6DCr9` (CRE "Writing to Solana" forwarder directory, both verified on devnet), `execution: "don"`, the runner's EVM trigger address in `authorizedKeys` (`{type: "KEY_TYPE_ECDSA_EVM", publicKey}`). New `live-devnet` target in `workflow.yaml` and `project.yaml`, private (Chainlink-hosted) registry. |
| Runner | `GatewayTrigger`: JSON-RPC `workflows.execute` to the CRE gateway, signed with an EVM key as an `alg: ETH` JWT, following `cre-sdk-typescript/packages/cre-http-trigger` (sorted-key JSON digest, EIP-191 signature, recovery id 0/1). Env: `CRE_GATEWAY_URL`, `CRE_WORKFLOW_ID`, `CRE_GATEWAY_PRIVATE_KEY`. Replaces the local `cre workflow simulate` when set. |
| Guard | No code change. New treasury with GuardConfig: live forwarder program and state, the deployed workflow owner, same `policy_hash`. |

## Isolation from the demo

The workflow refuses to report when the treasury's GuardConfig names a different forwarder, so the simulator workflow cannot write to a live treasury and the live workflow cannot write to a simulated one. The guard enforces the same on chain.

## Order

1. Workflow `don` execution (tests first).
2. Runner `GatewayTrigger` (tests first).
3. Trigger key, `config.live.json`, targets.
4. With approval: `cre secrets create`, `cre workflow deploy`, `cre workflow activate` on `live-devnet`.
5. Owner check: GuardConfig is immutable, so learn the workflow owner the live forwarder reports before creating the live treasury (deploy output and `cre account list-key`, then one review against a throwaway treasury if still unknown). Record the evidence in `evidence/cre/`.
6. Live treasury, `devnet.json` guard block on this branch, end-to-end clean and lookalike payments.

## Not solved here

Confidential execution: without Confidential Workflows enrollment the `don` execution lets node operators see the policy at run time. It is not in source, logs or reports. Say so in the demo. Workflow ID binding stays out (frozen GuardConfig, and the ID changes on every update).
