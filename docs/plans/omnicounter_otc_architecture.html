No proof, no payout. Trade-bound transaction verification and confidential policy enforcement on Squads v4, orchestrated by Chainlink CRE

↓

Guard: Request ReviewOn-chain review handshake

4.1 Guard Program

request_review( settlement_intent_hash: [u8; 32], trade_ref_hash: [u8; 32] ) accounts: multisig, vault_transaction, proposal, review (init), payer
  • Validate Squads account ownership
  • Validate vault tx / proposal ↔ multisig linkage and tx index
  • Review PDA ["review", multisig, tx_index] uses init, so a second review for the same tx fails
  • Compute msg_hash = SHA-256 of the VaultTransaction account data, on-chain (single definition of the tx hash)
  • Bind the settlement intent and trade ref

Chainlink CRE WorkflowProof before payout + confidential policy

5.1 Trigger

Listener (EC2) subscribes to guard logs via NOWNodes WebSocket logsSubscribe, backfills with getSignaturesForAddress, dedupes, then calls the CRE HTTP trigger with identifiers only.

POST /review { review, multisig, txIndex }

The workflow trusts nothing in the payload beyond identifiers and re-reads everything from chain. CRE Solana log trigger only if verified working.

5.2 Fetch + Cross-Check Solana State

Finalized reads of Review, VaultTransaction and destination token account owner.

Heliusoptional, if time

  • Sources compare decoded fields, not raw responses

Disagree → RPC_NO_CONSENSUS; hash differs → TX_HASH_MISMATCH

5.3 Semantic Decoder (pure TS)

Turn the exact transaction into structured actions for policy evaluation.

DecodedAction { kind: "TOKEN_TRANSFER", mint: "EPjF...USDC", source: "TREASURY_ATA", destination_owner: "8FK...2Qa", amount: "500000000000" }

Also detects authority changes, delegates, account closes, durable nonce instructions, unknown programs, Address Lookup Tables and extra instructions.

5.4 Fetch Off-chain Truth + Client Leg

  • Authoritative TradeRecord (version, status, expiry)
  • Counterparty Registry
  • Compliance / sanctions / wallet risk
  • Exposure / limits
Client leg check (NOWNodes Tron / Ethereum RPC): USDT Transfer to desk_deposit_address amount >= 500,250 USDT confirmations >= N deposit tx not already used by another trade

Proof before payout: no confirmed client leg → COUNTERPARTY_LEG_NOT_RECEIVED.

5.5 Trade Match + Confidential Policy

  • Trade status = SETTLEMENT_READY
  • Recompute settlement_intent_hash and trade_ref_hash from the trade; must equal the Review
  • Client leg received on-chain
  • Network / asset / amount match
  • Destination owner = verified settlement wallet
  • Wallet not sanctioned, risk check passed
  • No unexpected instructions
  • No authority changes, delegates or closes
  • No durable nonce instruction
  • Only allowlisted programs
  • Trade not expired / cancelled / settled
  • Per-trade + daily limits pass

Trade ticket fetch and sensitive rules run inside the CRE Confidential Workflow (TEE). Rules are versioned; their hash is fixed in GuardConfig.

5.6 Verdict + Report

Report (Borsh, fixed 171 bytes) { review: Pubkey, verdict: u8, // 1 approve, 2 reject reason: u16, // ReviewReason msg_hash: [u8; 32], settlement_intent_hash: [u8; 32], trade_ref_hash: [u8; 32], policy_hash: [u8; 32], expires_at: i64 // min(policy expiry, trade valid_until) }

Delivered with SolanaClient.writeReport; the DON signs it and the Keystone Forwarder verifies the signatures. Plain-English summary is template-based, never AI.

6
Result & Human ApprovalWrite verdict, then governance

6.1 Keystone Forwarder → Guard.on_report(metadata, report)

The forwarder verifies the DON signatures. The guard then checks:

  • Forwarder state account owned by GuardConfig.forwarder_program
  • forwarder_authority = PDA ["forwarder", state, guard_id] and is a signer
  • Payload exact length, verdict in {1, 2}, reason in table
  • Review exists and is PENDING
  • msg_hash, settlement_intent_hash, trade_ref_hash equal the Review
  • policy_hash == GuardConfig.policy_hash (else PolicyMismatch)
  • Store reason / policy_hash / expiry; set APPROVED or REJECTED; emit DecisionRecorded

Demo: cre workflow simulate --broadcast uses Chainlink's simulator mock forwarder on devnet (7kuE...cNK), so the same forwarder checks run in the demo.

7
Execute SettlementThe guard is the only execution path

7.1 Anyone Can Call

Operator clicks Execute Settlement in Next.js. The app calls the guard, never Squads execute directly (humans have no Execute permission).

7.2 Guard.guarded_execute()

  • Review.status == APPROVED
  • Clock::get() < Review.expires_at
  • Squads proposal == APPROVED
  • Re-hash current VaultTransaction data == Review.msg_hash
  • Review.multisig / tx_index match the VaultTransaction
  • Instructions sysvar address verified, then instruction 0 is not AdvanceNonceAccount (else DurableNonceDetected)
  • CPI target == Squads program ID SQDS4ep6...pCf
  • Set status EXECUTED before the CPI (one-way, single use)

7.3 Executor PDA

Seeds ["executor", multisig]. Only Squads member with Execute permission. Signs only the vault_transaction_execute CPI via invoke_signed().

7.4 Squads Execution

Guard ↓ invoke_signed() Executor PDA ↓ CPI Squads vaultTransactionExecute() ↓ Treasury / Settlement Vault ↓ Counterparty USDC account

SETTLEMENT EXECUTED ✓

Guard emits Executed. The listener records signature, slot and review, updates the activity feed and marks the trade SETTLED in the trade system (mock API).

Trust & Security Boundaries

Frontend: untrusted
May propose and display, but cannot authorize or bypass the guard.
Listener: untrusted trigger
Only passes identifiers. If it is down, reviews do not start and nothing executes (fail closed).
RPC providers: cross-checked
Native SolanaClient (DON consensus) plus NOWNodes; disagreement fails closed.
Chainlink CRE / DON: trusted computation
BFT capability execution; confidential trade data and rules in TEE.
Keystone Forwarder
Verifies DON signatures. Guard verifies the forwarder state owner and authority PDA.
Guard program: enforcement root
Only path that can execute Squads settlement through the executor PDA. Config immutable.
On-chain state: public
Review stores hashes, verdict, reason and expiry, never trade details.

Non-Negotiable Execution Invariant

APPROVED TRADE INTENT + CLIENT LEG RECEIVED ON-CHAIN + CROSS-CHECKED SOLANA STATE + TRADE ↔ TRANSACTION EXACT MATCH + CONFIDENTIAL POLICY PASS (policy_hash matches) + VALID FORWARDER-DELIVERED CRE REVIEW, NOT EXPIRED + 3 OF 3 SQUADS HUMAN APPROVALS + UNCHANGED msg_hash, NO DURABLE NONCE = SETTLEMENT MAY EXECUTE (ONCE)

If the system cannot prove all required conditions, it fails closed.
