# Phase 6 Anchor source gate

Status on 6 October 2026: no Anchor instruction has been approved for payout decoder support. The Wysiwys guard program and its IDL are now in `main`, but there is no approved non-MVP target program, instruction allowlist, or reviewed canonical mapping for a payout action. `deployments/devnet.json` is still absent. The decoder therefore continues to classify every non-MVP program as `unknown_program`.

The separate `inspectVaultTransaction` preview can interpret scalar fields from a caller-supplied Anchor IDL while retaining raw bytes. This does not add any Anchor program to the payout decoder or satisfy this source gate. `decodeVaultTransaction` still returns `unknown_program` for non-MVP programs.

For each proposed Anchor program, the team needs to provide the exact deployed program ID, a pinned IDL artifact with source/version provenance, the instruction names allowed for decoding, and a reviewed mapping from encoded arguments and account positions to decoder-local canonical action fields. The IDL's `address`, explicit instruction discriminator bytes, `accounts`, `args`, and referenced types must agree with the pinned deployed implementation. Anchor supports custom discriminator bytes, so the decoder must use the pinned IDL values rather than derive them from instruction names. Sources: [Solana's Anchor IDL guide](https://github.com/solana-foundation/developer-content/blob/main/docs/programs/anchor/idl.md) and [Anchor 0.31 custom discriminator notes](https://www.anchor-lang.com/docs/updates/release-notes/0-31-0).

The decoder reads only the ordered top-level compiled instructions inside a Squads `VaultTransactionMessage`. It does not observe any CPI or inner instruction that a supported Anchor program might execute, and an IDL alone cannot establish downstream effects. It also has no chain-state view of token-account owners, mints, or balances. Any action mapping must describe encoded facts only. Unknown program IDs, unknown discriminators, invalid arguments, and account-role mismatches must remain non-success. Each approved instruction needs a complete positive fixture and mismatch fixtures before support is enabled.

The actual Wysiwys CRE workflow target is still absent, so the Phase 5 project integration gate remains open. Phase 6 source-dependent decoding waits for the program and IDL decisions above. The provisional decoder contract stays in `packages/decoder`; `packages/shared` is unchanged.
